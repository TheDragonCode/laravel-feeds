# Génération et planification

Pour générer tous les flux actifs, utilisez la commande suivante :

```bash
php artisan feed:generate
```

Tous les flux actifs (`is_active = true`) de la table `feeds`, ou de celle indiquée dans le fichier `config/feeds.php`, seront alors exécutés.

:::tip
Lorsque vous appelez la commande sans paramètre, la console affiche des liens vers tous les flux, y compris ceux dont la propriété `is_active` vaut `false`.

Ces flux ne sont toutefois pas exécutés : ils sont marqués avec le statut `SKIP`.
:::

## Flux unique {/* #single_feed */}

:::warning
Le flux indiqué **sera exécuté**, même s’il est désactivé dans la table `feeds` de la base de données.
:::

Pour générer un flux particulier, appelez la commande `feed:generate` en lui passant comme paramètre l’identifiant du flux dans la table `feeds` :

```bash
php artisan feed:generate 123
```

## Sortie pour les agents d’IA {/* #ai_agent_output */}

Lorsque `feed:generate` s’exécute dans un agent de codage IA reconnu par [Laravel Agent Detector](https://github.com/laravel/agent-detector), la commande écrit automatiquement un seul objet JSON au lieu des barres de progression et des lignes d’état formatées. Aucune option de commande n’est requise. En dehors d’un agent reconnu, la sortie habituelle de la console reste inchangée.

Lors d’une génération directe, chaque flux généré contient tous les fichiers publiés et leur nombre d’enregistrements :

```json
{
  "tool": "feed:generate",
  "result": "success",
  "feeds": [
    {
      "class": "App\\Feeds\\SitemapFeed",
      "status": "generated",
      "files": [
        {
          "path": "/var/www/html/storage/app/public/sitemap.xml",
          "records": 1250
        }
      ]
    },
    {
      "class": "App\\Feeds\\DisabledFeed",
      "status": "skipped"
    }
  ]
}
```

La commande émet un JSON compact sur une seule ligne. L’exemple est mis en forme uniquement pour faciliter la lecture.

| Statut | Signification | Champs supplémentaires |
| --- | --- | --- |
| `generated` | Les fichiers du flux ont été générés directement. | `files`, avec `path` et `records` pour chaque fichier |
| `queued` | Le mode file d’attente est activé et le job du flux a été exécuté de manière synchrone pour l’agent. | Aucun |
| `skipped` | Le flux est inactif et la commande a été exécutée sans identifiant de flux. | Aucun |

:::note
En mode file d’attente, le chemin propre à l’agent exécute chaque job actif de manière synchrone avant de renvoyer le résultat JSON. Le chemin habituel, formaté pour les humains, continue d’envoyer les jobs via la connexion de file d’attente configurée.
:::

Cette enveloppe JSON est utilisée uniquement pour les exécutions réussies. Si la génération lève une exception, Laravel traite normalement l’erreur de la commande et n’émet aucune enveloppe d’erreur JSON.

## File d’attente {/* #queue */}

Par défaut, la génération des flux s’exécute dans le processus de console. Pour les flux longs à générer ou gourmands en mémoire, activez le mode Laravel Queue dans votre environnement :

```bash
FEED_QUEUE_ENABLED=true
FEED_QUEUE_CONNECTION=redis
FEED_QUEUE_NAME=feeds
FEED_QUEUE_UNIQUE_TTL=3600
```

Lorsque le mode file d’attente est activé, `feed:generate` envoie un job pour chaque flux actif au lieu de générer directement les fichiers. Avec une connexion asynchrone, la commande se termine après l’envoi des jobs. Démarrez un [worker de file d’attente](https://laravel.com/docs/queues#running-the-queue-worker) pour la connexion et la file sélectionnées afin de traiter ces jobs.

- `FEED_QUEUE_CONNECTION` sélectionne la connexion de file d’attente. À défaut, `QUEUE_CONNECTION`, puis `database`, sont utilisés.
- `FEED_QUEUE_NAME` sélectionne une file sur cette connexion. Laissez cette variable non définie pour utiliser la file par défaut de la connexion.
- `FEED_QUEUE_UNIQUE_TTL` définit en secondes la durée de vie maximale du verrou d’unicité. Tant que ce verrou est actif, aucun second job n’est ajouté pour le même flux.

:::note
La connexion `sync` exécute immédiatement chaque job dans le processus de console. Sélectionnez une connexion asynchrone pour transférer la génération à un worker. Définissez `FEED_QUEUE_ENABLED=false` pour générer directement les flux sans envoyer de jobs.
:::

## Planification {/* #schedule */}

### Automatique {/* #automatic */}

Pour automatiser la génération des flux, utilisez une [planification](https://laravel.com/docs/scheduling#running-the-scheduler). Ajoutez pour cela l’appel du helper dans le fichier `routes/console.php`, qui est le chemin par défaut sauf si vous l’avez modifié :

```php source="docs/snippets/schedule-setup.php" lines="5-"
use DragonCode\LaravelFeed\Helpers\ScheduleFeedHelper;
use Illuminate\Support\Facades\Schedule;

ScheduleFeedHelper::register();

Schedule::call(function () {
    // ... other action
})->everySecond();
```

Vous pourrez ainsi enregistrer les appels de tous les flux actifs selon la planification indiquée dans la colonne `expression` de la base de données.

### Manuelle {/* #manual */}

Vous pouvez également définir directement la planification selon vos propres règles. Dans ce cas, seuls les flux indiqués seront exécutés.

```php source="docs/snippets/schedule-setup-manual.php" lines="5-"
use DragonCode\LaravelFeed\Commands\FeedGenerateCommand;
use Illuminate\Support\Facades\Schedule;

Schedule::command(FeedGenerateCommand::class, [111])
    ->withoutOverlapping()
    ->runInBackground()
    ->daily();

Schedule::command(FeedGenerateCommand::class, [222])
    ->withoutOverlapping()
    ->runInBackground()
    ->hourly();

Schedule::call(function () {
    // ... other action
})->everySecond();
```
