# Guide de mise à niveau

<PageLead>
Cette documentation couvre actuellement la série `2.x`. Consultez les notes de version et le verrou des dépendances avant chaque mise à jour.
</PageLead>

La version `2.x` nécessite Laravel `13.x` et PHP `8.4` ou une version `8.x` ultérieure prise en charge. Mettez à jour les environnements web, CLI, du planificateur et des workers de file d’attente avant de modifier les contraintes Composer. Les applications utilisant Laravel `11.x` ou `12.x`, ou PHP `8.2` ou `8.3`, doivent rester sur `1.x`.

## Avant la mise à niveau {/* #before-upgrading */}

1. Vérifiez que la version cible prend en charge les versions PHP et Laravel de l’application.
2. Validez `composer.lock` et le fichier `config/feeds.php` actuellement publié.
3. Notez les enregistrements actifs et les destinations des fichiers générés.
4. Exécutez les tests de génération ou produisez des flux représentatifs hors production.

## Appliquer la mise à jour {/* #apply-update */}

```bash
composer require dragon-code/laravel-feeds:^2.0 --with-all-dependencies
```

Pour une installation existante, copiez uniquement `database/migrations/2026_10_14_000000_add_slug_to_feeds_table.php` du paquet dans le répertoire des migrations de votre application. Choisissez un horodatage de nom de fichier immédiatement après la migration `create_feeds_table` réellement présente dans l’application et avant toute migration d’enregistrement de flux ; conservez le suffixe `add_slug_to_feeds_table`. Exécutez ensuite `php artisan migrate`. La migration utilise la connexion et la table configurées et remplit les slugs à partir des titres existants, y compris les enregistrements supprimés temporairement. Ne republiez pas et ne réexécutez pas la migration d’origine qui crée la table. Remplacez les identifiants numériques des flux dans les commandes et les planifications manuelles par les slugs enregistrés.

```bash
php artisan migrate
```

Comparez le fichier `config/feeds.php` du paquet installé à la copie publiée et fusionnez les nouvelles clés manuellement. Ne republiez pas avec `--force` : cela écrase les valeurs propres à l’application.

## Vérifier {/* #verify */}

- Générez un flux pour chaque format utilisé.
- Vérifiez le nombre et le nom des fichiers fractionnés.
- Vérifiez la génération planifiée et en file d’attente.
- Vérifiez les modèles, transformateurs, macros et sous-classes de préréglage personnalisés.
- Comparez une sortie représentative avec la version précédente.

## Revenir en arrière {/* #rollback */}

Restaurez les anciens `composer.lock` et configuration, exécutez `composer install`, puis appliquez la politique d’annulation des migrations de l’application. Les fichiers générés sont des artefacts de déploiement ; restaurez-les ou régénérez-les selon le plan de reprise du stockage.
