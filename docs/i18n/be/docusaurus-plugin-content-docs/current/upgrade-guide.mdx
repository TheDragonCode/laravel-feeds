# Кіраўніцтва па абнаўленні

<PageLead>
Гэта дакументацыя апісвае лінейку выпускаў `2.x`. Перад кожным абнаўленнем правярайце нататкі да выпуску пакета і файл блакіроўкі залежнасцей.
</PageLead>

Версія `2.x` патрабуе Laravel `13.x` і PHP `8.4` або навейшай падтрымліваемай версіі `8.x`. Абнавіце асяроддзі вэб-запытаў, CLI, планавальніка і воркераў чаргі перад зменай абмежаванняў Composer. Праграмы на Laravel `11.x` або `12.x`, ці на PHP `8.2` або `8.3`, павінны заставацца на `1.x`.

## Перад абнаўленнем {/* #before-upgrading */}

1. Пераканайцеся, што мэтавая версія падтрымлівае версіі PHP і Laravel праграмы.
2. Зафіксуйце `composer.lock` і бягучы апублікаваны `config/feeds.php`.
3. Запішыце актыўныя рэгістрацыі стужак і месцы выходных файлаў.
4. Запусціце тэсты генерацыі праграмы або згенеруйце тыповыя стужкі не ў вытворчым асяроддзі.

## Прымяненне абнаўлення {/* #apply-update */}

```bash
composer require dragon-code/laravel-feeds:^2.0 --with-all-dependencies
```

Пры абнаўленні існуючай устаноўкі скапіруйце з пакета толькі `database/migrations/2026_10_14_000000_add_slug_to_feeds_table.php` у каталог міграцый прыкладання. Задайце timestamp імя файла адразу пасля фактычнай міграцыі `create_feeds_table` прыкладання і перад усімі міграцыямі рэгістрацыі стужак; захавайце суфікс `add_slug_to_feeds_table`. Затым выканайце `php artisan migrate`. Міграцыя выкарыстоўвае наладжаныя падключэнне і табліцу і запаўняе slug з існуючых назваў, уключаючы мякка выдаленыя запісы. Не публікуйце паўторна і не запускайце зыходную міграцыю стварэння табліцы. Замяніце лікавыя ідэнтыфікатары стужак у камандах і ручных раскладах захаванымі slug.

```bash
php artisan migrate
```

Параўнайце `config/feeds.php` усталяванага пакета з апублікаванай копіяй праграмы і дадайце новыя ключы ўручную. Не публікуйце паўторна з `--force`: гэта перазапісвае спецыфічныя налады праграмы.

## Праверка {/* #verify */}

- Згенеруйце па адной стужцы для кожнага выкарыстанага фармату.
- Праверце колькасць падзеленых файлаў і іх імёны.
- Праверце генерацыю па раскладзе і праз чаргу.
- Праверце карыстальніцкія мадэлі стужак, пераўтваральнікі, макрасы і падкласы перадусталёвак.
- Параўнайце тыповы вывад з папярэдняй версіяй.

## Адкат {/* #rollback */}

Аднавіце папярэднія `composer.lock` і канфігурацыю, выканайце `composer install` і прымяніце палітыку адкату міграцый праграмы. Згенераваныя файлы — артэфакты разгортвання; аднавіце або згенеруйце іх зноў паводле плана аднаўлення сховішча.
