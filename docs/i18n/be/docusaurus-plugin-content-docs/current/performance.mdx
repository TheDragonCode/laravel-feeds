# Прадукцыйнасць на вялікіх наборах даных

<PageLead>
Laravel Feeds запісвае даныя паступова. Памяць застаецца абмежаванай толькі тады, калі кожны папярэдні крок праграмы застаецца лянівым.
</PageLead>

## Пакідайце запыт лянівым {/* #lazy-query */}

Вяртайце `Builder` Eloquent непасрэдна:

```php
public function builder(): Builder
{
    return Product::query()
        ->select(['id', 'title', 'updated_at'])
        ->where('is_exportable', true);
}
```

Не матэрыялізуйце ўвесь вынік перад генерацыяй. Выбірайце толькі патрэбныя слупкі і загадзя загружайце толькі сувязі, якія выкарыстоўвае `item()`, каб пазбегнуць запытаў N+1.

## Наладжвайце памер блока {/* #chunk-size */}

Стандартнае значэнне — `1000` запісаў. Меншыя значэнні зніжаюць максімальны расход памяці мадэлямі і павялічваюць колькасць запытаў. Большыя значэнні памяншаюць накладныя выдаткі запытаў і павялічваюць расход памяці. Вымярайце з памерамі радкоў, блізкімі да вытворчых.

```php
public function chunkSize(): int
{
    return 500;
}
```

## Падзяляйце выходныя файлы {/* #split-output */}

Выкарыстоўвайце `perFile()`, калі спажывец прымае некалькі файлаў або адзін вывад становіцца складана публікаваць і паўтараць.

```php
public function perFile(): int
{
    return 50000;
}

public function maxFiles(): int
{
    return 20;
}
```

## Адпраўляйце доўгія стужкі ў чаргу {/* #queue-long-running */}

Рэжым чаргі выносіць генерацыю з кансольнай каманды, але не памяншае памяць, патрэбную стужцы. Выкарыстоўвайце асінхроннае падключэнне, запускайце апрацоўшчыкі з адпаведнымі абмежаваннямі часу і памяці і задавайце TTL унікальнасці большым за чаканы час генерацыі.

## Вымярайце ўвесь шлях {/* #measure */}

Асобна вымярайце час базы даных, стварэння мадэляў, пераўтварэння, серыялізацыі і публікацыі ў сховішча. Аддалены дыск можа стаць асноўным выдаткам нават пры хуткай генерацыі.
