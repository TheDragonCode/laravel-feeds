# Guia de atualização

<PageLead>
Esta documentação cobre a linha `2.x`. Revise as notas da versão e o arquivo de bloqueio das dependências antes de cada atualização.
</PageLead>

A versão `2.x` exige Laravel `13.x` e PHP `8.4` ou uma versão `8.x` posterior compatível. Atualize os ambientes web, CLI, do agendador e dos workers de fila antes de alterar as restrições do Composer. Aplicações que usam Laravel `11.x` ou `12.x`, ou PHP `8.2` ou `8.3`, devem permanecer na versão `1.x`.

## Antes de atualizar {/* #before-upgrading */}

1. Confirme que a versão de destino aceita as versões de PHP e Laravel da aplicação.
2. Faça commit de `composer.lock` e do `config/feeds.php` publicado.
3. Registre os feeds ativos e os destinos dos arquivos gerados.
4. Execute os testes de geração ou gere feeds representativos fora de produção.

## Aplicar a atualização {/* #apply-update */}

```bash
composer require dragon-code/laravel-feeds:^2.0 --with-all-dependencies
```

Para uma instalação existente, copie somente `database/migrations/2026_10_14_000000_add_slug_to_feeds_table.php` do pacote para o diretório de migrations da aplicação. Escolha um timestamp no nome do arquivo imediatamente após a migration `create_feeds_table` efetivamente presente na aplicação e antes de todas as migrations de registro de feeds; mantenha o sufixo `add_slug_to_feeds_table`. Em seguida, execute `php artisan migrate`. A migration usa a conexão e a tabela configuradas e preenche os slugs a partir dos títulos existentes, incluindo registros excluídos logicamente. Não publique nem execute novamente a migration original que cria a tabela. Substitua os IDs numéricos dos feeds nos comandos e agendamentos manuais pelos slugs armazenados.

```bash
php artisan migrate
```

Compare o `config/feeds.php` do pacote instalado com a cópia publicada e mescle as novas chaves manualmente. Não publique novamente com `--force`: ele sobrescreve valores da aplicação.

## Verificar {/* #verify */}

- Gere um feed para cada formato usado.
- Verifique a quantidade e os nomes dos arquivos divididos.
- Confirme a geração agendada e em fila.
- Confirme modelos, transformadores, macros e subclasses de predefinições personalizados.
- Compare uma saída representativa com a versão anterior.

## Reverter {/* #rollback */}

Restaure `composer.lock` e a configuração anteriores, execute `composer install` e aplique a política de rollback das migrations. Arquivos gerados são artefatos de implantação; restaure-os ou gere-os novamente conforme o plano de recuperação.
