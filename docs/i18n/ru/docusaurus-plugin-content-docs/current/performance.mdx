# Производительность на больших наборах данных

<PageLead>
Laravel Feeds записывает данные постепенно. Память остаётся ограниченной, только если каждый предыдущий шаг приложения остаётся ленивым.
</PageLead>

## Оставляйте запрос ленивым {/* #lazy-query */}

Возвращайте `Builder` Eloquent напрямую:

```php
public function builder(): Builder
{
    return Product::query()
        ->select(['id', 'title', 'updated_at'])
        ->where('is_exportable', true);
}
```

Не материализуйте весь результат до генерации. Выбирайте только нужные столбцы и заранее загружайте только связи, которые использует `item()`, чтобы избежать запросов N+1.

## Настраивайте размер блока {/* #chunk-size */}

Значение по умолчанию — `1000` записей. Меньшие значения снижают пиковый расход памяти моделями и увеличивают число запросов. Большие значения уменьшают накладные расходы запросов и повышают расход памяти. Измеряйте на строках производственного размера.

```php
public function chunkSize(): int
{
    return 500;
}
```

## Разделяйте выходные файлы {/* #split-output */}

Используйте `perFile()`, если потребитель принимает несколько файлов или один вывод становится сложно публиковать и повторять.

```php
public function perFile(): int
{
    return 50000;
}

public function maxFiles(): int
{
    return 20;
}
```

## Отправляйте долгие фиды в очередь {/* #queue-long-running */}

Режим очереди выносит генерацию из процесса консоли, но не уменьшает память, нужную фиду. Используйте асинхронное подключение, обработчики с подходящими ограничениями и TTL уникальности больше ожидаемого времени генерации.

## Измеряйте весь путь {/* #measure */}

Отдельно измеряйте базу данных, создание моделей, преобразование, сериализацию и публикацию. Удалённый диск может стать основной затратой даже при быстрой генерации.
