# 업그레이드 가이드

<PageLead>
현재 문서는 `1.x` 릴리스 계열을 다룹니다. 업데이트 전에 패키지 릴리스 노트와 의존성 잠금 파일을 검토하십시오.
</PageLead>

## 업그레이드 전 {/* #before-upgrading */}

1. 대상 버전이 애플리케이션의 PHP 및 Laravel 버전을 지원하는지 확인하십시오.
2. `composer.lock`과 현재 게시된 `config/feeds.php`를 커밋하십시오.
3. 활성 피드 등록과 생성 파일 위치를 기록하십시오.
4. 애플리케이션의 피드 생성 테스트를 실행하거나 프로덕션 외부에서 대표 피드를 생성하십시오.

## 업데이트 적용 {/* #apply-update */}

```bash
composer update dragon-code/laravel-feeds --with-all-dependencies
```

기존 설치에서는 패키지의 `database/migrations/2026_10_14_000000_add_slug_to_feeds_table.php`만 애플리케이션의 마이그레이션 디렉터리에 복사하십시오. 파일 이름의 타임스탬프는 애플리케이션의 실제 `create_feeds_table` 마이그레이션 바로 다음이면서 모든 피드 등록 마이그레이션보다 앞서도록 정하고, `add_slug_to_feeds_table` 접미사는 유지하십시오. 그런 다음 `php artisan migrate`를 실행하십시오. 이 마이그레이션은 구성된 연결과 테이블을 사용하여 소프트 삭제된 레코드를 포함한 기존 제목에서 slug를 채웁니다. 원래 테이블 생성 마이그레이션을 다시 게시하거나 실행하지 마십시오. 명령과 수동 스케줄의 숫자 피드 ID를 저장된 slug로 바꾸십시오.

```bash
php artisan migrate
```

설치된 패키지의 `config/feeds.php`와 애플리케이션의 게시된 파일을 비교하고 새 키를 직접 병합하십시오. `--force`로 다시 게시하지 마십시오. 애플리케이션별 값이 덮어써집니다.

## 검증 {/* #verify */}

- 사용 중인 각 형식의 피드를 하나씩 생성하십시오.
- 분할 파일 수와 파일 이름을 확인하십시오.
- 예약 생성과 큐 생성을 확인하십시오.
- 사용자 지정 피드 모델, 트랜스포머, 매크로 및 프리셋 하위 클래스를 확인하십시오.
- 대표 출력을 이전 버전과 비교하십시오.

## 롤백 {/* #rollback */}

이전 `composer.lock`과 구성을 복원하고 `composer install`을 실행한 다음 애플리케이션의 마이그레이션 롤백 정책을 적용하십시오. 생성 파일은 배포 산출물이므로 저장소 복구 계획에 따라 복원하거나 다시 생성하십시오.
