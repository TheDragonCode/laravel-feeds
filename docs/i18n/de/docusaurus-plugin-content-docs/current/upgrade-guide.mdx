# Upgrade-Leitfaden

<PageLead>
Diese Dokumentation behandelt derzeit die Versionsreihe `2.x`. Prüfen Sie vor jedem Update die Versionshinweise des Pakets und Ihre Abhängigkeitssperre.
</PageLead>

Version `2.x` erfordert Laravel `13.x` und PHP `8.4` oder eine neuere unterstützte Version der Reihe `8.x`. Aktualisieren Sie die Laufzeitumgebungen für Web, CLI, Scheduler und Queue-Worker, bevor Sie die Composer-Anforderungen ändern. Anwendungen mit Laravel `11.x` oder `12.x` oder mit PHP `8.2` oder `8.3` müssen bei `1.x` bleiben.

## Vor dem Upgrade {/* #before-upgrading */}

1. Prüfen Sie, ob die Zielversion die PHP- und Laravel-Versionen der Anwendung unterstützt.
2. Committen Sie `composer.lock` und die aktuell veröffentlichte `config/feeds.php`.
3. Erfassen Sie aktive Feed-Registrierungen und Ziele der erzeugten Dateien.
4. Führen Sie die Feed-Generierungstests der Anwendung aus oder erzeugen Sie repräsentative Feeds außerhalb der Produktion.

## Update anwenden {/* #apply-update */}

```bash
composer require dragon-code/laravel-feeds:^2.0 --with-all-dependencies
```

Kopieren Sie bei einer bestehenden Installation nur `database/migrations/2026_10_14_000000_add_slug_to_feeds_table.php` aus dem Paket in das Migrationsverzeichnis Ihrer Anwendung. Wählen Sie für den Dateinamen einen Zeitstempel unmittelbar nach der tatsächlichen `create_feeds_table`-Migration der Anwendung und vor allen Migrationen zur Feed-Registrierung; behalten Sie das Suffix `add_slug_to_feeds_table` bei. Führen Sie dann `php artisan migrate` aus. Die Migration verwendet die konfigurierte Verbindung und Tabelle und erzeugt Slugs aus bestehenden Titeln, einschließlich vorläufig gelöschter Datensätze. Veröffentlichen Sie die ursprüngliche Migration zum Erstellen der Tabelle nicht erneut und führen Sie sie nicht erneut aus. Ersetzen Sie numerische Feed-IDs in Befehlen und manuellen Zeitplänen durch die gespeicherten Slugs.

```bash
php artisan migrate
```

Vergleichen Sie `config/feeds.php` des installierten Pakets mit der veröffentlichten Kopie der Anwendung und übernehmen Sie neue Schlüssel manuell. Veröffentlichen Sie nicht erneut mit `--force`: Dies überschreibt anwendungsspezifische Werte.

## Prüfen {/* #verify */}

- Erzeugen Sie je einen Feed für jedes verwendete Format.
- Prüfen Sie Anzahl und Namen aufgeteilter Dateien.
- Prüfen Sie geplante und über Queues ausgeführte Generierung.
- Prüfen Sie eigene Feed-Modelle, Transformer, Makros und Unterklassen von Voreinstellungen.
- Vergleichen Sie eine repräsentative Ausgabe mit der vorherigen Version.

## Zurücksetzen {/* #rollback */}

Stellen Sie die vorherige `composer.lock` und Konfiguration wieder her, führen Sie `composer install` aus und wenden Sie die Migrations-Rollback-Richtlinie der Anwendung an. Erzeugte Dateien sind Deployment-Artefakte; stellen Sie sie gemäß dem Wiederherstellungsplan des Speichers wieder her oder erzeugen Sie sie erneut.
