# Швидкодія на великих наборах даних

<PageLead>
Laravel Feeds призначений для поступового запису даних. Використання пам'яті залишається обмеженим, лише коли застосунок зберігає кожен попередній крок ледачим.
</PageLead>

## Зберігайте запит ледачим {/* #lazy-query */}

Повертайте побудовник Eloquent `Builder` безпосередньо:

```php
public function builder(): Builder
{
    return Product::query()
        ->select(['id', 'title', 'updated_at'])
        ->where('is_exportable', true);
}
```

Не завантажуйте повний результат до генерування. Вибирайте лише потрібні стовпці та заздалегідь завантажуйте лише ті зв'язки, які використовує `item()`, щоб уникнути запитів N+1.

## Налаштуйте розмір блока {/* #chunk-size */}

Типове значення — `1000` записів. Менші значення зменшують пікове використання пам'яті моделями та збільшують кількість запитів. Більші значення зменшують витрати на запити та збільшують використання пам'яті. Вимірюйте з розмірами рядків, подібними до виробничих.

```php
public function chunkSize(): int
{
    return 500;
}
```

## Розділяйте вихідні файли {/* #split-output */}

Використовуйте `perFile()`, коли споживачі приймають кілька файлів або один файл стає складно публікувати та повторно обробляти.

```php
public function perFile(): int
{
    return 50000;
}
```

Залишайте для `maxFiles()` типове значення `0`, якщо потрібно експортувати всі відповідні записи. Коли `perFile()` і `maxFiles()` більші за нуль, Laravel Feeds експортує не більше їхнього добутку й успішно завершує генерування, не повідомляючи про пропущені наступні записи. Задавайте `maxFiles()` лише для навмисного обмеження кількості записів.

## Передавайте тривалі фіди до черги {/* #queue-long-running */}

Режим черги виносить генерування з консольного запиту, але не зменшує обсяг пам'яті, який використовує фід. Використовуйте асинхронне підключення, запускайте обробники з належними обмеженнями часу та пам'яті й задавайте час дії блокування унікальності довшим за очікуваний час генерування.

## Вимірюйте весь шлях {/* #measure */}

Окремо вимірюйте час роботи бази даних, створення моделей, перетворення, серіалізації та публікації у сховищі. Для віддалених дисків публікація може стати основною витратою, навіть коли саме генерування швидке.
