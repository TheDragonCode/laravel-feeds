# Посібник з оновлення

<PageLead>
Документація зараз охоплює гілку випусків `2.x`. Перед кожним оновленням перевіряйте примітки до випуску пакета та файл блокування залежностей.
</PageLead>

Версія `2.x` потребує Laravel `13.x` і PHP `8.4` або новішої підтримуваної версії `8.x`. Оновіть середовища вебзастосунку, CLI, планувальника й обробників черги до зміни обмежень Composer. Застосунки на Laravel `11.x` або `12.x` чи PHP `8.2` або `8.3` мають залишатися на `1.x`.

## Перед оновленням {/* #before-upgrading */}

1. Переконайтеся, що цільова версія підтримує версії PHP і Laravel застосунку.
2. Збережіть у коміті `composer.lock` і поточний опублікований `config/feeds.php`.
3. Запишіть активні реєстрації фідів і призначення згенерованих файлів.
4. Запустіть тести генерування фідів застосунку або згенеруйте показові фіди в невиробничому середовищі.

## Застосування оновлення {/* #apply-update */}

```bash
composer require dragon-code/laravel-feeds:^2.0 --with-all-dependencies
```

Під час оновлення наявного встановлення скопіюйте з пакета лише `database/migrations/2026_10_14_000000_add_slug_to_feeds_table.php` до каталогу міграцій застосунку. Задайте timestamp імені файлу відразу після фактичної міграції `create_feeds_table` застосунку й перед усіма міграціями реєстрації фідів; збережіть суфікс `add_slug_to_feeds_table`. Потім виконайте `php artisan migrate`. Міграція використовує налаштовані підключення й таблицю та заповнює slug із наявних назв, включно з м’яко видаленими записами. Не публікуйте повторно й не запускайте початкову міграцію створення таблиці. Замініть числові ідентифікатори фідів у командах і ручних розкладах на збережені slug.

```bash
php artisan migrate
```

Порівняйте `config/feeds.php` установленого пакета з опублікованою копією застосунку та додайте нові ключі вручну. Не публікуйте файл повторно з `--force`: це перезапише значення застосунку.

## Перевірка {/* #verify */}

- Згенеруйте по одному фіду для кожного використаного формату.
- Перевірте кількість і назви розділених файлів.
- Перевірте генерування за розкладом і через чергу.
- Перевірте власні моделі фідів, перетворювачі, макроси та успадковані шаблони.
- Порівняйте показове виведення з попередньою версією.

## Відкат {/* #rollback */}

Відновіть попередні `composer.lock` і конфігурацію, виконайте `composer install` і застосуйте політику відкоту міграцій застосунку. Згенеровані файли є артефактами розгортання; відновіть або згенеруйте їх повторно відповідно до плану відновлення сховища.
