# 升级指南

<PageLead>
当前文档涵盖 `2.x` 发布系列。每次更新前，请查看软件包发布说明和依赖锁文件。
</PageLead>

版本 `2.x` 需要 Laravel `13.x` 和 PHP `8.4` 或受支持的更高 `8.x` 版本。更改 Composer 约束之前，请升级 Web、CLI、调度器和队列进程的运行环境。使用 Laravel `11.x` 或 `12.x`，或 PHP `8.2` 或 `8.3` 的应用必须继续使用 `1.x`。

## 升级前 {/* #before-upgrading */}

1. 确认目标版本支持应用的 PHP 和 Laravel 版本。
2. 提交 `composer.lock` 和当前发布的 `config/feeds.php`。
3. 记录已启用的 Feed 注册项和生成文件目标位置。
4. 运行应用的 Feed 生成测试，或在非生产环境中生成有代表性的 Feed。

## 应用更新 {/* #apply-update */}

```bash
composer require dragon-code/laravel-feeds:^2.0 --with-all-dependencies
```

对于已有安装，只需将软件包中的 `database/migrations/2026_10_14_000000_add_slug_to_feeds_table.php` 复制到应用的迁移目录。选择文件名的时间戳，使该迁移紧接应用实际的 `create_feeds_table` 迁移，并且位于所有 Feed 注册迁移之前；保留 `add_slug_to_feeds_table` 后缀。然后运行 `php artisan migrate`。该迁移使用配置的连接和表，根据现有标题填充 slug，包括已软删除的记录。不要重新发布或运行原始的建表迁移。将命令和手动调度中的数字 Feed ID 替换为已存储的 slug。

```bash
php artisan migrate
```

将已安装软件包的 `config/feeds.php` 与应用发布的副本进行比较，并手动合并新键。不要使用 `--force` 重新发布，因为它会覆盖应用专用值。

## 验证 {/* #verify */}

- 为每种已用格式生成一个 Feed。
- 验证拆分文件的数量和文件名。
- 确认计划和队列生成正常。
- 确认自定义 Feed 模型、转换器、宏和预设子类正常。
- 将代表性输出与以前版本进行比较。

## 回滚 {/* #rollback */}

恢复以前的 `composer.lock` 和配置，运行 `composer install`，并应用该应用的迁移回滚策略。生成文件是部署产物；请根据存储恢复计划还原或重新生成它们。
