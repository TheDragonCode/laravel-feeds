# Multiple targeted feed files

This recipe registers one `PartnerFeed` and uses feed targets to generate multiple XML files. Each target provides parameters that `builder()` uses for its own query conditions and `filename()` uses for its own output path. Partners are only the example; a target could represent a store, locale, region, or any other business condition.

## Feed targets versus perFile() {/* #targets-vs-per-file */}

`perFile()` splits one query result into sequential files after a fixed number of records. The query and selection conditions stay the same across those files.

`FeedTarget` runs the feed separately for every target. The application can therefore use `target()` to change the query conditions and filename for each output. Both mechanisms can be combined: select a target-specific dataset first, then split that dataset by record count.

This example creates the following target files:

```text
storage/app/public/partners/42.xml
storage/app/public/partners/81.xml
```

## Create the feed {/* #create-feed */}

```bash
php artisan make:feed Partner
```

## Configure partner outputs {/* #configure-partner-outputs */}

Replace the generated feed class with:

```php source="docs/snippets/targeted-feed.php"
<?php

declare(strict_types=1);

namespace App\Feeds;

use App\Models\Partner;
use App\Models\Product;
use DragonCode\LaravelFeed\Concerns\InteractsWithFeedTargets;
use DragonCode\LaravelFeed\Contracts\HasFeedTargets;
use DragonCode\LaravelFeed\Feeds\Feed;
use DragonCode\LaravelFeed\Feeds\FeedTarget;
use Illuminate\Database\Eloquent\Builder;

class PartnerFeed extends Feed implements HasFeedTargets
{
    use InteractsWithFeedTargets;

    public function targets(): iterable
    {
        foreach (Partner::query()->select('id')->lazyById() as $partner) {
            yield $this->makeTarget($partner);
        }
    }

    public function findTarget(string $key): ?FeedTarget
    {
        $partner = Partner::query()->find($key);

        if (! $partner || (string) $partner->getKey() !== $key) {
            return null;
        }

        return $this->makeTarget($partner);
    }

    public function builder(): Builder
    {
        return Product::query()->where(
            'partner_id',
            $this->target()->parameters['partner_id'],
        );
    }

    public function filename(): string
    {
        return "partners/{$this->target()->key}.xml";
    }

    private function makeTarget(Partner $partner): FeedTarget
    {
        return new FeedTarget(
            key       : (string) $partner->getKey(),
            parameters: ['partner_id' => $partner->getKey()],
        );
    }
}
```

`targets()` enumerates partners lazily for full runs. `findTarget()` resolves explicitly requested keys without loading every partner. `builder()` filters products for the active partner, and `filename()` gives every partner a unique path.

```bash
# For Laravel Deploy Operations
php artisan operations

php artisan migrate
```

## Generate all partner files {/* #generate-all */}

Pass the feed registration ID. The command generates a file for every partner returned by `targets()`:

```bash
php artisan feed:generate 123
```

With partners `42` and `81`, the generated paths are:

```text
storage/app/public/partners/42.xml
storage/app/public/partners/81.xml
```

## Generate selected partner files {/* #generate-selected */}

Use the repeatable `--target` option when only specific partners need fresh files:

```bash
php artisan feed:generate 123 --target=42
php artisan feed:generate 123 --target=42 --target=81
```

## Split each partner output by record count {/* #split-each-output */}

Add `perFile()` when one partner output can also become too large:

```php
public function perFile(): int
{
    return 50000;
}
```

Partner `42` can then produce `partners/42-1.xml`, `partners/42-2.xml`, and later parts. This record-count split is applied independently to every partner.
