# Eloquent

In `2.3.0`, `FeedObserver::saving()` assigns `$feed->slug = $feed->title`; `SlugCast` then applies `Str::slug()`. This runs on every event-enabled model `create()`, `update()`, or `save()`, even when `title` is unchanged, and overwrites a manually supplied slug. For example, `Products` becomes `products`.

The observer reads the current `title` property, including modern and legacy accessors, after any setters already applied. It does not read the raw stored title or guarantee the final value written to the database. An accessor returning `Display: Stored: Product Catalog` produces `display-stored-product-catalog`. Keep display-only formatting in a separate accessor if it should not affect slugs.

`saveQuietly()` and saves inside `withoutEvents()` skip the observer. Changing `title` this way leaves the previous slug unchanged unless the application assigns it explicitly. Use a normal save when events are wanted. For a quiet save with the same derivation as the observer:

```php
use DragonCode\LaravelFeed\Models\Feed;

$feed = Feed::query()->findOrFail(42);
$feed->title = 'New Title';
$feed->slug = $feed->title;
$feed->saveQuietly();
```

If a later `saving` listener, or a `creating` or `updating` listener, changes `title`, the package does not recalculate the slug afterward. Prefer setting the title before saving or using a title mutator. If a listener must change it later, assign `$feed->slug = $feed->title` immediately after that change in the same listener; do not call `save()` recursively. Check the listener order in application tests.

When saving a partially selected model, include `title` and every attribute required by its accessor. There is no guard that preserves the slug when `title` is missing. Query Builder bulk inserts and updates do not run this observer; maintain both values explicitly for those writes. Preserve the inherited observer and casts in custom models.

Choose titles that produce distinct, non-empty slugs for selected and scheduled feeds. A title that normalizes to an empty slug cannot be selected. Multiple non-deleted registrations with the same slug cause `Illuminate\Database\MultipleRecordsFoundException` on lookup; no suffix is added automatically.

## Custom feed registration model {/* #custom_feed_model */}

Set `feeds.model` to an application model when feed registration records need additional columns, casts, relationships, or methods. The custom model must extend `DragonCode\LaravelFeed\Models\Feed`.

```php
namespace App\Models;

use DragonCode\LaravelFeed\Models\Feed as BaseFeed;

class Feed extends BaseFeed
{
    protected $fillable = [
        'slug',
        'class',
        'title',
        'expression',
        'is_active',
        'last_activity',
        'is_foo',
        'is_bar',
    ];

    protected function casts(): array
    {
        return [
            ...parent::casts(),
            'is_foo' => 'boolean',
            'is_bar' => 'boolean',
        ];
    }
}
```

Register the model in `config/feeds.php`:

```php
'model' => App\Models\Feed::class,
```

Add the custom columns to the feeds table in an application migration. Keep every attribute accepted by mass assignment in `$fillable`.

`FeedQuery` uses the configured model for create, find, list, update, delete, and restore operations. Pass application-specific values through `extra` when creating a record. These values are applied last and can override the method arguments:

```php
$feed = app(FeedQuery::class)->create(
    class: SomeFeed::class,
    title: 'Some',
    expression: '0 */12 * * *',
    extra: [
        'is_foo' => true,
        'is_bar' => true,
    ]
);
```

The application model can also use the regular Eloquent API:

```php
use App\Models\Feed;

$feed = Feed::create([
    'class' => SomeFeed::class,
    'title' => 'Some',
    'expression' => '0 */12 * * *',
    'is_active' => true,
    'is_foo' => true,
    'is_bar' => true,
]);
```

:::note
The configured model is resolved at runtime. Static analysis sees the result of `FeedQuery::create()` as the package base model. Use `App\Models\Feed::create()` or an explicit local type when autocomplete for application-specific properties is required.
:::

## Chunk size {/* #chunk_size */}

Database queries use chunks, which are `1000` items by default. You can change this by overriding the `chunkSize` method:

```php source="docs/snippets/advanced-feed-chunk.php" lines="5-"
use DragonCode\LaravelFeed\Feeds\Feed;

class UserFeed extends Feed
{
    public function chunkSize(): int
    {
        return 500;
    }
}
```
