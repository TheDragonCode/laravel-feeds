# Feed listing timezone selection and test expectations diverged

**Date:** 2026-10-21 14:24
**Files:** src/Commands/FeedListCommand.php, tests/Feature/Console/ListTest.php, tests/.pest/snapshots/Feature/Console/ListTest/calculates_the_next_run_in_the_scheduler_timezone_with_data_set__dataset__null_scheduler_timezone__.snap
**Severity:** medium

## Problem

The full Pest suite reported 15 failures in feed listing tests. Expected UTC timestamps differed from the configured +01:00 output, and scheduler timezone overrides were ignored.

## Root Cause

The shared test setup changed app.timezone without changing PHP's default timezone. Feed listing expectations still derived their timezone from Carbon's default clock. Separately, getTimeZone() stopped reading app.schedule_timezone, contrary to Laravel's scheduler and the documented command behavior.

## Solution

Restore the scheduler override with an application timezone fallback for missing or null values. Convert only the expected next-run clock into the configured application timezone, preserving the shared UTC fixtures. Make UTC datasets configure UTC explicitly.

The null scheduler regression test failed with InvalidArgumentException before the null fallback fix and passed afterward. The final full suite passed: 579 tests, 4927 assertions. Pint and git diff --check passed. No diagnostic logging was added, following project rules.

## Prevention

- Keep command timezone selection aligned with the scheduler and documentation.
- Set timezone assumptions explicitly in test datasets when shared configuration changes.
- Cover both missing and null optional configuration values before using typed configuration getters.
