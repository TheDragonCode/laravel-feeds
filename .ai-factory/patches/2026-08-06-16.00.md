# Read-only storage docs used the unsupported adapter preflight contract

**Date:** 2026-08-06 16:00
**Files:** `docs/docs/location.mdx`, `docs/docs/troubleshooting.mdx`, `docs/docs/api/events-exceptions.mdx`, `docs/i18n/*/docusaurus-plugin-content-docs/current/location.mdx`, `docs/i18n/*/docusaurus-plugin-content-docs/current/troubleshooting.mdx`, `docs/i18n/*/docusaurus-plugin-content-docs/current/api/events-exceptions.mdx`, `docs/static/llms.txt`
**Severity:** medium

## Problem

The storage documentation stated that a Laravel read-only disk throws `UnsupportedStorageDiskException` before the feed query starts. Laravel still resolves that disk as `FilesystemAdapter`, so it passes the preflight type check and fails later when the generated feed is published.

## Root Cause

The documentation treated adapter type validation and write capability as the same preflight check. Laravel decorates the Flysystem adapter as read-only but continues to expose it through `FilesystemAdapter`. The publication callback therefore completes the feed query and local staging before the remote write fails inside the generation exception boundary.

## Solution

Separated the two failure contracts in the storage guide, troubleshooting guide, and exception reference. Custom disks that do not resolve as `FilesystemAdapter` fail before the query with `UnsupportedStorageDiskException`. Laravel read-only disks fail during publication, and `GeneratorService` wraps that storage failure in `FeedGenerationException`. Updated all maintained localizations and regenerated the LLM documentation artifact.

## Prevention

- Distinguish adapter type checks from filesystem capability failures in documentation.
- Trace framework decorators and exception boundaries before describing failure timing.
- Update duplicated API, troubleshooting, generated, and localized documentation together.
