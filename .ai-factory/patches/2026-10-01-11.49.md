# Documentation feed fixtures broke after storage path normalization

**Date:** 2026-10-01 11:49
**Files:** `tests/Helpers/docs.php`, `tests/Unit/DocsTest.php`, `tests/Datasets/receipts.php`, `workbench/app/Feeds/Docs/*.php`, `docs/snippets/receipt-*-feed.php`
**Severity:** medium

## Problem

Fourteen documentation feature tests failed with `PathTraversalDetected` on Laravel 13.34.0. The paths started with nine `../` segments followed by `docs/snippets/`.

## Root Cause

The fixtures relied on `Storage::path()` concatenating paths without normalization. The test disk root contained nine nested `storage` directories so fixture paths could walk back to the temporary workspace. Laravel now normalizes paths before prefixing the disk root.

Receipt source replacements also expected filenames without the `-feed` suffix, so they did not match the actual fixture filenames. Four generated PHP snippets retained the fixture traversal paths.

## Solution

Set the documentation disk root directly to `docsGeneratedDirectory()` and use plain XML filenames in all fourteen fixtures. Correct the receipt replacement keys and synchronize their four PHP snippets with the existing documentation examples.

Add a regression test that checks the resolved path and writes through the disk to that same generated snippet path. It failed with `PathTraversalDetected` before the fix and passed afterward. Existing optional workspace diagnostics remain available without adding logging.

The full Pest suite passed on Laravel 13.34.0 and in an isolated Laravel 12.69.3 runtime: 435 tests and 2244 assertions on each version. Pint and `git diff --check` passed. The documentation snippet check still reports four existing unreferenced `receipt-*-feed.xml` files.

## Prevention

- Configure the disk root to match the test output directory instead of escaping it through relative paths.
- Verify that fixture filenames and snippet replacement keys match exactly.
- Check both normalized and legacy storage path behavior when updating framework dependencies.
