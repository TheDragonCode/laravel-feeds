# Locale search payloads and legacy introduction redirect

**Date:** 2026-08-06 19:16
**Files:** docs/docusaurus.config.ts, docs/routes.json, docs/scripts/content-manifest.mjs, docs/static/search/*.json, docs/src/components/DocSearch/index.tsx, docs/tests/e2e.spec.ts
**Severity:** medium

## Problem

Opening documentation search downloaded one combined payload containing page bodies for all nine locales even though only the active locale was used. The legacy `/introduction.html` bookmark also redirected to the new homepage instead of the equivalent `/introduction/` guide.

## Root Cause

The content manifest stored route metadata and every localized search index in one imported `routes.json` file. The search component selected the active locale only after downloading and parsing that full file. The legacy redirect retained the old homepage target after the introduction content moved to its own route.

## Solution

Kept route metadata in `routes.json`, emitted one static search JSON file per configured locale, and fetched only the active locale when search opens. Failed index requests remain retryable after the dialog is reopened. Retargeted `/introduction.html` to `/introduction/` and added browser coverage for the redirect, locale-specific network request, and retry behavior.

## Prevention

- Keep large locale-specific client payloads in independently loadable assets.
- Verify lazy-loading changes through observed browser requests, not only rendered behavior.
- Keep failed loads distinct from valid empty results so transient errors remain retryable.
- Recheck legacy redirects when a route changes from content page to landing page.
