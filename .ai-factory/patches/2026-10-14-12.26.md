# Archived documentation used current search and LLM content

**Date:** 2026-10-14 12:26
**Files:** `docs/src/components/DocSearch/index.tsx`, `docs/scripts/content-manifest.mjs`, `docs/scripts/build-llms.mjs`, `docs/scripts/version-docs.mjs`, `docs/scripts/check-built-site.mjs`, `docs/tests/e2e.spec.ts`, `docs/tests/versioned-llms.spec.ts`
**Severity:** medium

## Problem

Search results on 1.x pages linked to current 2.x documentation. Archived machine-learning pages also linked to the current llms.txt, which contained incompatible PHP and Laravel requirements.

## Root Cause

Search assets and the cached index were keyed only by locale. The LLM generator read only current sources. Creating a documentation snapshot did not create matching generated assets or update the copied LLM links.

## Solution

Generate indexes from each version's frozen sources and select them through Docusaurus active-version context. Key cached results by the complete asset URL and ignore stale requests. Generate a separate LLM bundle per version and link it from all nine archived locales. Extend snapshot creation and rollback to cover these assets, and validate their built routes. Current generated outputs remain byte-identical.

## Prevention

- Reproduce archive search and LLM regressions before the fix; both failed against the original build.
- Cover locale and version switches, delayed search responses, home and unknown routes, and frozen LLM requirements and links.
- Validate snapshot creation in an isolated copy, including generated assets for every locale.
- Production build, SEO checks, all 40 browser tests, and 8 PHP documentation tests passed after the fix.
