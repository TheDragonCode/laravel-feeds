# Performance guide silently capped split exports

**Date:** 2026-08-06 17:07
**Files:** `docs/docs/performance.mdx`, `docs/i18n/*/docusaurus-plugin-content-docs/current/performance.mdx`, `docs/static/llms.txt`
**Severity:** high

## Problem

The large-dataset performance guide combined `perFile()` set to `50000` with `maxFiles()` set to `20` without explaining that the example exports at most 1,000,000 records. Additional matching records were omitted while generation still completed successfully.

## Root Cause

The guide presented `maxFiles()` only as part of file splitting and did not trace its interaction with `perFile()` through `ExportService::capacity()`. The service multiplies both positive values and applies the result to the model stream with `take()`.

## Solution

Removed `maxFiles()` from the copyable splitting example so the default exports every matching record. Added an explicit warning that positive `perFile()` and `maxFiles()` values cap the export at their product without reporting omitted records. Synchronized all maintained localizations and regenerated the LLM documentation artifact.

## Prevention

- Treat output limits as record-loss contracts, not only file-layout settings.
- Trace documentation examples through query bounds before recommending them for large datasets.
- Keep safety warnings synchronized across source documentation, localizations, and generated artifacts.
