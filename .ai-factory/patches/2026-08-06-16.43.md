# FeedStartingEvent documentation implied draft readiness

**Date:** 2026-08-06 16:43
**Files:** `docs/docs/events.mdx`, `docs/docs/api/events-exceptions.mdx`, `docs/i18n/*/docusaurus-plugin-content-docs/current/events.mdx`, `docs/i18n/*/docusaurus-plugin-content-docs/current/api/events-exceptions.mdx`, `docs/static/llms.txt`
**Severity:** medium

## Problem

The event reference stated that `FeedStartingEvent` is dispatched immediately before draft creation. The event actually fires before converter resolution and publication staging, so either setup step can fail without any draft file being created.

## Root Cause

The documentation inferred the event boundary from the later export phase instead of tracing the call order in `GeneratorService::feed()`. Storage and path preflight complete first, then `FeedStartingEvent` is dispatched, and only afterward does the service resolve the converter and enter `FilesystemService::publishTo()`.

## Solution

Documented `FeedStartingEvent` as the start of generation after storage and path preflight but before converter resolution and staging. Clarified that the event does not guarantee a draft file exists. Updated the API reference, events guide, all maintained localizations, and the generated LLM documentation artifact.

## Prevention

- Derive lifecycle documentation from the exact call order around event dispatch.
- Do not treat a start event as a resource-readiness guarantee unless the implementation creates that resource first.
- Keep duplicated event contracts and all maintained localizations synchronized.
