# Legacy FeedJob payload left target uninitialized

**Date:** 2026-08-07 01:42
**Files:** src/Jobs/FeedJob.php, tests/Unit/Jobs/FeedJobTest.php
**Severity:** high

## Problem

A worker running the updated package could fail while processing a `FeedJob` serialized by the previous release. The old payload had no `target` field, so reading it raised `Typed property DragonCode\LaravelFeed\Jobs\FeedJob::$target must not be accessed before initialization`.

## Root Cause

The nullable constructor-promoted property used a parameter default, not a declared property default. PHP unserialization does not run the constructor, so an old payload without the new field left the typed property uninitialized.

## Solution

Declared `target` as a regular public property initialized to `null`, accepted the same nullable constructor argument, and assigned it explicitly. Added a regression test that removes the field before serialization to reproduce a pre-upgrade payload.

## Prevention

- Give newly added typed properties explicit defaults when objects may outlive a deployment through serialization.
- Test backward compatibility with payloads that omit newly introduced fields.
- Run queue serialization tests against both current and legacy object shapes.
