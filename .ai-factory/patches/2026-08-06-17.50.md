# Documentation search skipped page bodies and accessible labels stayed English

**Date:** 2026-08-06 17:50
**Files:** `docs/routes.json`, `docs/scripts/content-manifest.mjs`, `docs/scripts/check-i18n.mjs`, `docs/src/components/DocSearch/index.tsx`, `docs/tests/e2e.spec.ts`, `docs/i18n/*/docusaurus-plugin-content-docs/current/compatibility.mdx`
**Severity:** medium

## Problem

Documentation search indexed only metadata and headings, so identifiers present in page bodies, including `deleteByClass` and `FEED_QUEUE_NAME`, returned no results. The compatibility table also exposed the English accessible name in every translated locale.

## Root Cause

The generated search entries did not contain normalized page content. The localization check ignored literal user-facing MDX attributes because tag lines were excluded from its translatable text comparison.

## Solution

Added normalized body content to every locale's search entries and included it in matching. Loaded the enlarged search manifest only when the search dialog opens to preserve the initial JavaScript budget. Added an end-to-end regression test for both reviewed identifiers. Extended localization validation to compare literal user-facing MDX attributes and translated the compatibility table label in all eight maintained locales.

## Prevention

- Cover metadata, headings, and body-only identifiers in documentation search tests.
- Treat literal accessibility and presentation attributes in MDX as translatable content.
- Keep large client-side search data outside the initial page bundle.
