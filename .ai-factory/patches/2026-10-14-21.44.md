# Protected cache members broke existing transformer subclasses

**Date:** 2026-10-14 21:44
**Files:** `src/Transformers/DateTimeTransformer.php`, `tests/Unit/Transformers/DateTimeTest.php`
**Severity:** medium

## Problem

Existing `DateTimeTransformer` subclasses could fail to load when they already declared `configuration()`, `$configuration`, or `$transforming` with unrelated types.

## Root Cause

The configuration cache introduced protected members into an extensible class. PHP required matching inherited signatures and property types, although these names had previously been available to consumers.

## Solution

Made the three cache members private while preserving the original protected extension points. Added independent regression tests for the method and both property collisions. Each test reproduced a fatal declaration error before the fix and passed afterward, checking the formatted date and unchanged consumer members.

## Prevention

- Keep new implementation details private in extensible package classes.
- Test subclasses with existing members of the same name and incompatible types.
- Verify parent internals do not dispatch to or overwrite unrelated consumer members.
